Traditional XOOPS vs Vision 2026

See how Clean Architecture transforms XOOPS module development

Quick Comparison

Aspect Traditional XOOPS Vision 2026
Validation Scattered throughout code Centralized in Value Objects
Database Access Anywhere ($xoopsDB->query) Only in Infrastructure layer
Testing Requires XOOPS + database Domain tests run standalone
Business Rules Mixed with UI/DB code Isolated in Domain Entities
Dependencies Everything depends on XOOPS Core code has zero dependencies
Reusability Locked to XOOPS Domain logic works anywhere
❌ Traditional Approach
Creating an Article
Everything mixed in one file
// submit.php - validation, DB, redirect all together
$title = $_POST['title'];

// Validation scattered here
if (strlen($title) > 255) {
    $error = 'Title too long';
    redirect_header('add.php', 2, $error);
}

// Database code right here
global $xoopsDB;
$sql = "INSERT INTO...";
$xoopsDB->queryF($sql);

// Hard to test without XOOPS running!
  • Validation mixed with database code
  • Same validation duplicated in 5+ places
  • Can't test without full XOOPS bootstrap
  • Easy to forget validation somewhere
✅ Vision 2026 Approach
Creating an Article
Clean separation of concerns
// Controller: thin, delegates to handler
$command = new CreateArticle(
    ArticleTitle::fromString($_POST['title']),
    ArticleContent::fromString($_POST['content']),
    AuthorId::fromInt($uid)
);

// Handler does the work
$article = $handler->handle($command);

// Validation happens in Value Objects - once!
  • Value Objects validate at creation
  • Handler is easily unit tested
  • No database code in controller
  • Type safety prevents wrong values
❌ Validation Scattered 
// In submit.php:
if (strlen($title) > 255) { ... }

// In edit.php (different check!):
if (!$title) { ... }

// In api.php:
// Forgot validation entirely!

// In import.php:
if (empty($title)) { ... }

Different validation in different places. Bugs waiting to happen.

✅ Validation Centralized 
// ArticleTitle.php - ONE place for all rules
final readonly class ArticleTitle
{
    public static function fromString($value): self
    {
        if ($value === '') {
            throw new InvalidArgumentException(...);
        }
        if (strlen($value) > 255) {
            throw new InvalidArgumentException(...);
        }
        return new self($value);
    }
}

One class, one place, always valid after creation.

🧪 Testing

Domain layer tests run in milliseconds with zero external dependencies. No database, no XOOPS bootstrap, no flaky tests.

📦 Value Objects

Self-validating data types like ArticleTitle, ArticleSlug, AuthorId. Impossible to have invalid data after creation.

🎯 Domain Events

Record what happened (ArticlePublished, CommentAdded) for loose coupling. Notifications, indexing, analytics - all decoupled.

🔄 Repository Pattern

Interface in Domain, implementation in Infrastructure. Swap databases without changing business logic.

✅ Testing is Easy 
public function test_article_creation(): void
{
    // No database! No XOOPS!
    $article = Article::create(
        ArticleTitle::fromString('Test'),
        ArticleContent::fromString('Content'),
        AuthorId::fromInt(1)
    );

    $this->assertTrue($article->isDraft());
}
// Runs in 23ms!
